# Выгрузка на reg.ru

Сайт собирается в статику — обычные HTML, CSS, JS и картинки. Node на хостинге
не нужен, подойдёт любой тариф виртуального хостинга.

## Сборка

```bash
npm ci
npm run build
```

Готовый сайт — папка `out/`. Внутри уже лежит `.htaccess`, его тоже нужно
выгрузить.

Первая сборка занимает около минуты: `scripts/generate-images.mjs` готовит
адаптивные версии всех фотографий. Повторные сборки почти мгновенные —
пересчитываются только изменённые файлы.

## Проверка перед выгрузкой

```bash
npm run preview
```

Поднимает `out/` на `http://localhost:3001` и раздаёт файлы ровно так, как это
сделает Apache: сначала файл, потом `index.html` внутри папки, потом `404.html`.
Если страница открывается здесь — откроется и на хостинге.

## Куда класть файлы

Содержимое `out/` кладётся в корень сайта — **содержимое, не саму папку**. На
reg.ru это обычно:

```
/var/www/<логин>/data/www/<домен>/
```

В файловом менеджере или по FTP это папка с именем вашего домена. Внутри должны
оказаться `index.html`, `.htaccess`, `_next/`, `img/` и папки разделов.

```
<домен>/
├── .htaccess
├── index.html
├── 404.html
├── _next/
├── img/
├── barbers/
├── book/
├── journal/
└── services/
```

**Через FTP** (FileZilla): подключиться данными из письма reg.ru, открыть папку
домена, перетащить туда всё содержимое `out/`, включая скрытый `.htaccess` — в
FileZilla скрытые файлы включаются в меню «Сервер → Принудительно отображать
скрытые файлы».

**Через файловый менеджер** в панели reg.ru: запаковать содержимое `out/` в zip,
загрузить, распаковать в папке домена.

## Проверка после выгрузки

1. Открыть домен — должна открыться главная.
2. Перейти по разделам: `/services/`, `/barbers/`, `/journal/`, `/book/`.
3. Открыть раздел напрямую по адресу, с обновлением страницы (F5) — так
   проверяется, что маршруты отдаёт сам Apache, а не JavaScript.
4. Открыть заведомо несуществующий адрес — должна показаться страница 404
   сайта, а не страница Apache.
5. Пройти запись на `/book/` до конца.

## Если что-то не открывается

**Разделы отдают 404, главная работает.** `.htaccess` не выгрузился — это
скрытый файл, FTP-клиенты часто их прячут. Проверьте, что он лежит в корне.

**Ошибка 500 на всём сайте.** Хостинг не понял какую-то директиву в
`.htaccess`. Все они обёрнуты в `<IfModule>` именно на этот случай, но если
это всё же случилось — переименуйте `.htaccess`, сайт заработает без сжатия и
кеширования, и напишите в поддержку reg.ru, какой модуль недоступен.

**Стили и картинки не подгрузились.** Файлы выгружены в подпапку, а не в корень
домена. Пути в сборке абсолютные (`/_next/...`). Либо перенесите файлы в корень,
либо задайте `basePath` в `next.config.ts` и пересоберите.

## Домен и почта в текстах

Адрес сайта прописан один раз — `metadataBase` в `src/app/layout.tsx`. Название,
телефоны, адреса залов и почта — в `src/lib/content.ts`. После правок пересобрать
и выгрузить заново.
